# 待審分兩種：資料本身不合格，與換算暫時做不到

待審（quarantined）不是單一種狀態。**因外部暫時取不到匯率而待審的成交，會在下一輪爬取自動重試換算**；因資料本身不合格（多張一組、狀態不是 PSA 10）而待審的則不會自動復原，等待人工判定。

## Considered Options

原本 `CONTEXT.md` 把待審定義為「無法高信心確認為單張、PSA 10、屬於此卡種」——全是關於**這筆成交是什麼**。但 ADR-0006 要求每筆成交以成交當日匯率換算，而 ADR-0014 記錄了臺銀有間歇性的機器人保護。匯率抓不到時，那筆成交的身分沒有任何問題，只是**現在還換不成台幣**。

三個選項：

**用今日匯率先換、日後再修**：違反 ADR-0006 的「寫入即固定」，而且修不修得成沒人知道。編出來的數字一旦進入中位數就再也分不出來。

**匯率失敗就整輪爬取失敗**：一個外部來源的暫時性故障會讓成交紀錄完全抓不進來，連原幣都存不下。原幣是不可變更的原始資料，沒有理由因為換算失敗而不保存。

**進待審、下一輪重試**（採用）：原幣照樣入庫、換算欄位留空、狀態標為待審並附上原因。下一輪爬取時，凡是「待審原因為查無匯率且尚未換算」的成交都會再試一次。

## Consequences

- 臺銀被擋一次不會被固化成資料問題。若不重試，一次機器人驗證就會讓那一批成交永久躺在待審清單裡，看起來像資料有問題，實際上是被擋——那是 ADR-0014 點名的「安靜說謊」的變體。
- **重試只發生在換算欄位上**，原幣、原始狀態與枚数文字從寫入那刻起就不再變動。復原時寫入的匯率同樣一經寫入即固定。
- 匯率來源只回溯約六個月（ADR-0014）。早於涵蓋範圍的成交會在每一輪都重試一次並持續待審，這是正確的行為：它們確實換不出來，而且沒有假裝換得出來。
- 待審清單必須顯示原因，使用者才分得出「這筆被擋是因為它是一組五張」與「這筆只是還沒拿到匯率」。前者要人判斷，後者按一次更新行情就好。
- `CONTEXT.md` 的待審定義隨之放寬為兩類。
