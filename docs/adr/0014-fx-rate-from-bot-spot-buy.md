# 匯率取自臺灣銀行 L6M CSV 的即期買入價

JPY→TWD 的歷史匯率取自臺灣銀行的日圓近六個月牌告 CSV，路徑為 `/xrt/flcsv/0/L6M/JPY`（**L6M 必須大寫**），採用其中的**即期買入**價。

## Considered Options

錄製腳本實測了五個候選來源，只有一個可用：

| 來源 | 實測結果 |
|---|---|
| 臺銀 `flcsv/0/L6M/JPY`（大寫） | **可用**。124 個營業日、22 欄、同列含買入與賣出、現金與即期 |
| 臺銀 `flcsv/0/l6m/JPY`（小寫） | 200，但內容是「很抱歉，本次查詢找不到任何一筆資料！」 |
| 臺銀 `flcsv/0/day` | 200，但內容是機器人驗證頁 |
| 臺銀 `xrt/quote/l6m/JPY`（HTML） | 第一次可用（124 列），第二次被機器人驗證擋下 |
| 央行 `lp-644-1.html` | 200，但回的是外匯存底頁 |
| 央行 `np-1053-1.html` | 200，內容是 52 bytes 的轉址 stub |

**五個來源中有四個回 200 卻沒有資料。** 狀態碼漂亮、內容是空的——若以狀態碼判斷成功，整條匯率鏈會安靜地建立在空資料上。錄製腳本因此改為檢查內容特徵，不信任狀態碼。

央行原本是偏好選項（使用者經驗上較好抓），但實測其公開頁面並未直接提供 JPY→TWD；若要走央行就得用美元交叉匯率（JPY/USD × USD/TWD），那是兩次換算的誤差疊加，而且不會報錯。臺銀直接給 JPY→TWD，這個問題不存在。

**欄位選擇**：同一天有四個候選價（現金買入 0.19060、現金賣出 0.20340、即期買入 0.19790、即期賣出 0.20190，以 2026/08/25 為例）。

- **現金**價差最大，是實體現鈔換匯的牌告。賣掉一張卡不會提一袋日鈔回臺灣，用它會低估資產約 3.7%。
- **即期賣出**是你買日圓的價，方向錯了。
- **即期買入**對應的情境是「把卡在日本賣掉、把日圓換回台幣」——這正是市值要回答的問題，也是三者中最保守的，不會高估資產。

## Consequences

- 歷史只回溯約六個月（實測 2026/02/26 ～ 2026/08/25）。目前 `trades` 最多 20 筆、最遠約五個月，剛好落在範圍內。若日後需要更早的匯率，這個來源不夠，得另尋。
- CSV 一列同時含買入與賣出：欄位 [3] 現金買入、[4] 即期買入、[13] 現金賣出、[14] 即期賣出。
- **只有營業日**。實測 124 個日期全為週一至週五，另有 26 個缺口（週末與國定假日），全部需要沿用前一營業日——這正是 ADR-0006 預留的機制。
- **臺銀有間歇性的機器人保護**，且不針對特定端點。錄製跑了兩輪，同一個端點兩次結果相反：`flcsv/0/day` 第一輪被擋、第二輪正常；`xrt/quote/l6m/JPY` 第一輪正常、第二輪被擋。定案採用的 `flcsv/0/L6M/JPY` 目前只有一次成功觀測，不能假設它永遠可用。

  由此得出兩項實作要求：

  1. **必須偵測機器人驗證頁並視為明確失敗**。驗證頁是 200 且 content-type 為 `text/csv`，只有內容看得出來。若把它當成「查無匯率」，成交紀錄會被送進待審，看起來像資料問題，實際上是被擋——那是安靜說謊的變體。
  2. **爬取必須克制**：匯率只抓實際用得到的日期、已抓過的不重抓。ADR-0006 的「寫入即固定」本來就蘊含這件事。
- 匯率一併存下**來源**與**實際採用的日期**，日後換來源時分辨得出哪些數字來自哪裡。
