# 售出指定到單一持有品，日期預設今天且可覆寫

新增持有品時購入日預設今天，售出時售出日預設今天，兩者皆可覆寫。售出時系統列出該卡種所有持有中的持有品（含購入日與購入成本），由使用者指定賣掉的是哪一張，系統不自動挑選。

## Considered Options

**日期強制為今天**更防呆，但 Notion 匯入的 102 筆全為補登資料，且「前幾天賣掉、今天才記」是常態；強制今天會逼使用者每次繞去編輯功能改回來。

**售出時以先進先出（FIFO）或最高成本自動挑選持有品**可省去一次點擊，但已實現損益會變成「會計上的真」而非事實上的真，且使用者事後無從得知系統挑了哪一張。實際資料中 `S8b #187` 的 Charizard 有 7 筆持有品、成本 2,885–3,300，挑錯一張的已實現損益差距是實質的。共識書 C6 已定調：安靜說謊的儀表板比沒有儀表板更糟。共識書 Q1 把持有品與卡種分開建模，正是為了保住每一張的個別成本，自動挑選會把這個資訊丟掉。

## Consequences

- 售出動作的輸入是「某一筆持有品」而非「某個卡種」，UI 需要一個選擇步驟。
- 未售出的持有品，售出日與售出價一律為**空值**，不以 0 表示。0 會被誤讀為「以 0 元賣出」，已實現損益將算成 −100%。
- 持有中／已售出的判定一律看**售出日是否有值**，不看售出價。匯入與 CRUD 皆適用。
