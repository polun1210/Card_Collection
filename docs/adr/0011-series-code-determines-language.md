# 系列代碼不做收斂：`SVP` 與 `SV-P` 是不同語言的不同系列

`#3` 導入了一條正規化規則「`SVP` → `SV-P`」，假設兩者是同一個系列的兩種寫法。**這個假設是錯的**，規則已移除。系列代碼一律原樣使用，只去除前後空白。

| 代碼 | 系列 | 語言 |
|---|---|---|
| `SVP` | Scarlet & Violet Promo | 英文版 |
| `SV-P` | プロモーションカード | 日文版 |

Notion 資料中 `SVP` 有 2 筆（`131 Kingdra`、`132 Greninja`），皆為英文版；`SV-P` 有 3 筆，皆為日文版。收斂之後，系統拿著日版促銷卡的代碼去搜尋，撈回一批不相干的日文卡——使用者在人工確認時全數否決，錯誤才浮上來。

## Consequences

- **英文版卡不在範圍內**，兩張已自 `data/notion-export/pokemon_project.csv` 移除（持有品 102 → 100 筆，成本合計 1,188,010 → 1,164,010）。實體卡仍在使用者手上，但 SNKRDUNK 是日本市場、對英文版卡沒有行情來源，估不了價。
- **卡種數 70 → 68。** 數值與共識書的 68 相同但來源不同：共識書的 68 是「系列＋卡號」去重（方法錯、數字碰巧對），現在的 68 是「系列＋卡號＋卡名」去重（ADR-0008）再排除 2 張英文版。
- 已建立的資料庫保留這 2 列為「已否決」作為審計軌跡，不回頭刪除——刪除會動到同一張表裡已確認的 68 筆。
- 這條規則違反了本專案自己的詞彙表：`CONTEXT.md` 早已寫明「語言不是獨立屬性——**系列代碼本身已決定語言**」。正規化的職責是補齊寫法（卡號補零），不是替不同的東西改名。
- **這個錯誤不會報錯。** 若使用者日後再加入任何英文版卡，收斂規則會讓它被當成日版卡去估價，而畫面上一切正常。人工確認（共識書 A4）是唯一攔下它的機制，這次它做到了。
