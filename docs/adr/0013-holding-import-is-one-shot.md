# 持有品匯入是一次性的，記在帳本裡

Notion CSV 的持有品匯入只執行一次。完成後寫入匯入帳本（`holding_import`），之後每次啟動服務都跳過，不比對指紋、不做增量對齊。

## Considered Options

**每次啟動都對齊 CSV** 較符合直覺，也省掉一張表。但持有品**沒有天然唯一鍵**——來源 CSV 裡有 7 組欄位完全相同的列（例如 3 列一模一樣的 `S8b #187 Charizard`，成本皆 2,885），那是三張實體卡，不是重複資料。任何靠內容去重的對齊都會吃掉真實資產。

改用 CSV 列號當唯一鍵可以避開去重問題，但會製造更糟的行為：日後透過 CRUD 刪掉的持有品，會在下次重啟時自己長回來。使用者不會知道發生了什麼，只會看到刪掉的東西又出現。共識書 C6 已定調：安靜說謊的儀表板比沒有儀表板更糟。

CSV 是歷史補登的一次性入口；補登完成後，真實來源是 CRUD。帳本讓這件事在資料庫層面說得明白。

## Consequences

- 指紋（來源檔內容的 SHA-256）只作為事後對帳的佐證，不作為重跑的判斷依據。
- 要重新匯入，開發期間的作法是刪掉資料庫重來。沒有「重匯」或「修正匯入」的機制。
- 匯入資料不合格時整批失敗，服務起不來。錯誤訊息指出來源列號與卡種寫法，改完 CSV 重啟即可。帶著半份持有品把服務跑起來，比起不來更糟。
