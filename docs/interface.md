# 介面現況與交接

這份文件寫給**接手 UIUX 階段的人**。它回答三件事：現在的介面長什麼樣、哪些東西
**不能動**、哪些東西**已知該動但刻意還沒動**。

它不是設計規範，也不取代 `CONTEXT.md`。詞彙一律以 `CONTEXT.md` 為準，決策一律以
`docs/adr/` 為準——本文若與那兩者衝突，是本文錯了。

---

## 1. 技術現況（先知道這個，才不會提出做不到的設計）

- **沒有前端框架、沒有建置步驟**。三個頁面都是 Jinja2 樣板，CSS 寫在各頁的
  `<style>` 裡，JS 寫在各頁的 `<script>` 裡。改樣式＝改樣板，存檔重整就看得到。
- **零外部資源**。全站沒有任何 `<link>`、CDN、字型檔或圖示庫。這是刻意的：這是個
  跑在自己電腦上的個人工具，不該因為外部網站掛掉而變醜或變慢。
  - 副作用：`font-family` 指定了 `"Noto Sans TC"` 但**沒有載入它**，所以只有本機
    裝了才會生效，否則落到 `system-ui`。要用指定字型就得決定「要不要為此引入外部
    資源」，那是一個要明講的取捨。
- **JS 只做三件事**：走勢圖繪製與 hover、更新行情的按鈕、持有品增刪改的對話框，
  外加卡片展開時抓動能。**其餘畫面在沒有 JS 的情況下就是完整的**——分頁切換用的是
  `radio + :checked`，不等腳本。這個性質值得保留。
- 版面寬度：首頁與持有品頁 `max-width: 78rem`，卡種對應頁 `72rem`。

## 2. 三個頁面

| 路由 | 頁面 | 給誰用 | 樣板 |
|---|---|---|---|
| `/` | 收藏總覽 | **日常主畫面**，打開就看到自己的收藏 | `portfolio.html` |
| `/holdings` | 持有品逐筆明細 | 對帳用，一列一個卡種、逐筆展開 | `holdings.html` |
| `/queue` | 卡種對應（待確認清單） | 後台作業，把卡種對到 SNKRDUNK | `queue.html` |

`/` 是根路徑而 `/queue` 不是，這是刻意的：**這是收藏儀表板，不是後台工具**。

### `/` 收藏總覽的區塊（由上而下）

1. **總覽數字**（`.totals`）— 未實現損益、報酬率、已實現損益、持有中張數與成本、
   總市值、已售出張數
2. **行情新鮮度**（`.freshness`）— 上次成功更新是多久以前，超過 24 小時變警示色
3. **工具列**（`.toolbar`）— 更新行情、**新增持有品**、兩個頁面連結
4. **走勢圖**（`.trend`）— 總市值曲線疊總成本階梯線，底部一條涵蓋率量尺，
   區間鈕 `7D / 1M / 3M / YTD / ALL`
5. **卡圖牆**（`.wall`）— 一格一個卡種，分「持有中／已售出」兩個分頁

### 卡圖牆一格的結構

收合時（`<summary>`）顯示卡圖、卡名、系列代碼、報酬率；已售出的另外把成本、淨賺、
售出日也放在收合狀態就看得到（**終局的數字不必展開**）。

展開後（持有中）依序是：成本、市值、未實現損益、**動能**、**流動性**、每一張。
「每一張」逐筆列出購入日與成本，每一筆各自帶 `售出／編輯／刪除`。
已售出展開後是每一筆的售出日與售出價，各自帶 `改回持有中／編輯／刪除`。

## 3. 共用片段：行為共用，外觀不共用

`templates/` 底下 `_` 開頭的是被 `{% include %}` 進去的片段：

| 片段 | 內容 | 被誰用 |
|---|---|---|
| `_market_freshness.html` | 行情新鮮度的 markup | `/`、`/holdings` |
| `_market_script.html` | 更新行情按鈕的行為 | `/`、`/holdings` |
| `_holding_editor.html` | 持有品增刪改的對話框與行為 | `/`、`/holdings` |

**分工是刻意的：這些片段只共用行為與 markup，不共用樣式。** 對應的 CSS 各頁自己寫
一份。理由是版面預期會被重做，共用樣式會讓兩頁被綁在一起改——想單獨調整首頁時，
會發現動一行就把持有品頁也改了。

UIUX 階段若決定要建立共用的設計 token 或樣式表，**這個分工可以推翻**，但請當成一
個明確的決定去做（並補一張 ADR），不要順手改掉。

## 4. 目前的視覺語彙

| 用途 | 值 | 備註 |
|---|---|---|
| 上漲／獲利 | `#0b7a4b` | 綠 |
| 下跌／虧損／錯誤 | `#b91c1c` | 紅 |
| 警示（過期、匯率抓不到） | `#b45309` | 琥珀 |
| 次要文字 | `#6b7280` | 灰 |
| 框線 | `#d1d5db`（外）／`#e5e7eb`（內） | |
| 圖片底色／佔位 | `#f3f4f6` | 見下方待辦 |
| 連結、焦點 | `#2563eb` | |

其他慣例：

- **數字一律 `font-variant-numeric: tabular-nums`**（等寬數字），縱向對得齊
- **顏色只用在數字上**。走勢圖的線與涵蓋率量尺刻意用中性灰，不帶漲跌語意——
  那條線講的是「涵蓋多少」，不是「賺賠」
- **不足與空狀態各有各的表現**，三者刻意長得不一樣，不可以合併成同一種灰字：
  - 涵蓋率不足的區段 → 灰色斜線區 ＋ 虛線曲線（ADR-0021）
  - 這個卡種近期沒成交 → `.expired` 琥珀色「已過期 N 天」
  - 整個系統沒更新成功 → `.freshness.stale` 整塊變琥珀
- **指標還沒到位的空狀態** → `.soon` 虛線圓角標籤（「資料累積中」「敬請期待」）
  ＋ `.why` 一句說明為什麼

## 5. 不可協商的約束

以下每一條都來自 `CONTEXT.md` 或 ADR，**視覺重做時不能違反**。它們看起來像細節，
但每一條都是為了不讓畫面說謊。

1. **缺數字就讓它不存在，不顯示 0，也不顯示 `—` 以外的假值。**
   0 會被讀成「不賺不賠」「不漲不跌」，那是把缺資料講成一個結論。
2. **未實現損益與已實現損益永不混入同一個數字。** 兩者必須分開呈現。
3. **報酬率一律 `(結果 − 成本) ÷ 成本`，不使用倍數。** 全站唯一定義。
4. **市值旁必須並列樣本形狀**（幾筆成交／涵蓋哪段期間）。ADR-0015。
   一個由兩筆成交撐起來的價，與由二十筆撐起來的價，不該長得一模一樣。
5. **走勢圖必須逐日揭露涵蓋率。** ADR-0021。曲線不能只畫線而不說它涵蓋了幾張卡。
6. **行情新鮮度必須與市值出現在同一個畫面上。** 停擺的爬取若不出聲，三週前的數字
   看起來與今天的一模一樣。
7. **空狀態不是暫時的鷹架。** 新買進的卡種永遠會經歷「還沒有動能」的階段，資料補齊
   之後這個狀態依然存在。它要長得像刻意的設計，不是壞掉的畫面。
8. **流動性的兩個半邊必須並列**，不可以只先開熱門度那一半。存世多但成交少，與存世
   多且成交多，是完全不同的兩張卡。
9. **沒有市值的卡種仍然要留在牆上。** 消失會被讀成「我少了一張卡」，那比一格沒有
   數字嚴重得多。
10. **手機是主要的唯讀場景，首頁永不橫向捲動。** 卡圖牆用 `auto-fill` 自己換行，
    刻意不用表格。（`/holdings` 與 `/queue` 是對帳與後台，允許表格橫捲。）
11. **刪除持有品前必須明確確認，且說得出是具體哪一筆**（卡種、購入日、成本），
    已售出的還要說出會讓已實現損益少多少。不是一句抽象的「確定嗎」。

## 6. 已知該動、刻意還沒動

### 6.1 卡圖框比例錯了，每格浪費一半空間 ⭐ 優先

`aspect-ratio: 10/7` 出現在五處（`portfolio.html` ×1、`holdings.html` ×2、
`queue.html` ×2），搭配 `object-fit: contain` 與 `background: #f3f4f6`。

**它是個過期的值。** git 記錄很明確：

| commit | 事件 |
|---|---|
| `d3c1e76` | 待確認清單接上 SNKRDUNK，寫下 `aspect-ratio: 10/7` |
| `d82ce77` | **之後**才加入裁切（`images.py` 的 `crop_border`） |

`10/7` = 1.43，對應的是 SNKRDUNK **未裁切**的原圖畫布 1000×730（≈1.37）。裁切上線
後卡圖變成直的（約 0.72），這個值沒有回頭改，還被複製到另外兩頁。

實測全部 69 張卡圖，各候選值的留白比例：

| 值 | 比例 | 平均留白 | 最差 |
|---|---|---|---|
| `10/7`（現況） | 1.4286 | **49.6%** | 51.0% |
| `7/10` | 0.7000 | 2.6% | 36.1% |
| `5/7` | 0.7143 | **1.6%** | 34.8% |
| `63/88`（實體卡真實尺寸 63mm × 88mm） | 0.7159 | **1.6%** | 34.6% |

卡圖實際比例：最窄 0.700、中位 0.718、最寬 1.095。

**為什麼留給這個階段而不是順手改掉**：換值不是終點。改成直式後卡圖牆每格高度會從
約 10.7rem 變成約 17.6rem（**整面牆高約 1.6 倍，捲動距離 +65%**），會立刻逼出另外
三個決定，它們應該一起做：

- 格子寬 `minmax(9.5rem, 1fr)` 還合適嗎
- 要不要改用 `object-fit: cover`（裁掉邊緣填滿，留白歸零但會切到卡緣）
- 那塊 `#f3f4f6` 底色還要不要留

`5/7` 與 `63/88` 數據上並列最佳，差別在**哪個值自帶理由**——`63/88` 是實體卡的真實
尺寸，寫進 CSS 時註解自己就寫好了。

沒有任何測試鎖住這個值，改動不會有紅燈保護，也不會有紅燈阻擋。

### 6.2 一張卡圖裁切結果異常

`data/images/744296.webp`（MEGA Lucario 錯體版）是 **668×610，比例 1.095**，
其餘 68 張都在 0.70~0.72。就算換上最佳比例，它那一格仍會有約 35% 留白——
上表的「最差」欄就是它。推測是去背有雜點，讓 `Image.getbbox()` 裁不乾淨。

這是資料問題不是版面問題，但會在版面上現形，所以記在這裡。

### 6.3 深色模式只做了一半

三個頁面都宣告了 `color-scheme: light dark`，所以作業系統切深色時瀏覽器會給深色底，
**但所有顏色都是寫死的淺色系值**，沒有深色對應版本。最明顯的是 `#f3f4f6`（圖片
佔位底色）在深色模式下會變成一塊刺眼的亮白。

要嘛補齊深色版（`prefers-color-scheme` 或 CSS 變數），要嘛拿掉 `color-scheme` 宣告
只做淺色。**現在是兩者之間最糟的狀態**：宣告了支援，實際上沒支援。

### 6.4 三頁的樣式各寫一份

如 §3 所述這是刻意的。但 `.totals`、`.freshness`、`.toolbar`、`button` 等區塊在
`portfolio.html` 與 `holdings.html` 幾乎逐字相同。若這個階段要建立設計 token，
這幾塊是最明顯的起點。

## 7. 資料從哪裡來

畫面上的每個數字都是伺服器算好的，前端**不重算任何金額**。

| 端點 | 餵給誰 |
|---|---|
| `GET /api/portfolio` | 首頁的全部：總覽數字、走勢圖、新鮮度、卡圖牆 |
| `GET /api/cards/{apparel_id}/holdings` | 卡片**展開時**才取：動能、流動性、該卡種的持有品與市值 |
| `GET /api/cards/{apparel_id}/image` | 卡圖 |
| `POST /api/market/crawl` | 「更新行情」按鈕 |
| `POST/PATCH/DELETE /api/holdings...` | 增刪改對話框 |

兩個值得知道的設計：

- **走勢圖的資料一次全給**。`ALL` 是其他四個區間的超集合，切區間是在瀏覽器裡切片，
  零延遲、不打 API。
- **動能是展開那一刻才取的**，卡圖牆的列表回應不背負它。牆上有六十幾格，為了使用者
  實際會展開的那一兩格，把其餘全部都算一次並不划算。
