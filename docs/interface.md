# 介面現況與交接

這份文件寫給**之後接手介面的人**。它回答四件事：現在的介面長什麼樣、哪些東西
**不能動**、動手改的時候**測試會擋你哪裡**、哪些東西是**已知的限制**。

它描述的是 UI/UX 重做（#28，Premium Dark Gallery）**完成之後**的介面。重做的設計
意圖與施工細節在 `docs/uiux-spec.md`，CSS 架構決策在 ADR-0023——本文不重抄它們。

它不是設計規範，也不取代 `CONTEXT.md`。詞彙一律以 `CONTEXT.md` 為準，決策一律以
`docs/adr/` 為準——本文若與那兩者衝突，是本文錯了。

## 1. 技術現況（先知道這個，才不會提出做不到的設計）

- **沒有前端框架、沒有建置步驟**。三個頁面都是 Jinja2 樣板，JS 寫在樣板的
  `<script>` 裡。樣式是 `src/card_collection/static/` 底下的靜態 CSS，由 FastAPI
  掛在 `/static`。改樣式＝改 CSS 檔，存檔重整就看得到（`static_url()` 會在網址後面
  帶上檔案版本，不必手動清快取）。
- **零外部資源**。全站沒有任何 CDN、Web Font 或圖示庫。`/static` 底下全是本機檔案，
  這條規矩的意思是「**執行期不依賴外部網站**」。理由：這是個跑在自己電腦上的個人
  工具，不該因為別人的網站掛掉而變醜或變慢。
  - 字型用 system font stack（`--font-sans`），不載入 Noto Sans TC，中文落到系統字型。
- **只有深色，不跟作業系統切換**（ADR-0022）。`color-scheme: dark`，沒有淺色版。
- **JS 只做這幾件事**：走勢圖繪製與 hover、更新行情、持有品增刪改的對話框、
  卡片明細抽屜（開關、打開時抓動能、卡圖傾斜與反光，ADR-0024）、持有品與歷史的
  即時篩選、卡種對應的候選選取與確認。
- **分頁不靠 JS**：卡圖牆與對應歷史的分頁都是 `radio + :checked`。腳本壞掉時分頁
  照樣能切、卡圖照樣顯示。這個性質要保留。
- 版面寬度：`--content-max: 78rem`（收藏總覽、持有品），卡種對應覆寫為 `64rem`。
  手機斷點 `767px`。

## 2. 三個頁面

| 路由 | 頁面 | 角色 | 主要回答的問題 | 樣板 |
|---|---|---|---|---|
| `/` | 收藏總覽 | 收藏儀表板 | 我持有中的收藏值多少、有哪些卡、最近怎麼動 | `portfolio.html` |
| `/holdings` | 持有品 | 帳本／管理工作台 | 我要檢查或修改哪一筆實體持有品 | `holdings.html` |
| `/queue` | 卡種對應 | 對應調解工作區 | 哪個卡種需要人工對到 SNKRDUNK | `queue.html` |

`/` 是根路徑而 `/queue` 不是，這是刻意的：**這是收藏儀表板，不是後台工具**。

### 全站頁首（三頁共用，`_app_shell.html`）

```
┌───────────────────────────────────────────────────────────────────┐
│ Pokémon Collection   收藏總覽  持有品  卡種對應    更新行情  [＋ 新增持有品] │
└───────────────────────────────────────────────────────────────────┘
  手機：導覽收進「選單」（原生 <details>），不用釘在底部的導覽列
```

- `＋ 新增持有品` 是**唯一**的常駐主要動作。在卡種對應頁它是連到 `/holdings` 的連結。
- `更新行情` 是低調的文字按鈕，行情健康時也找得到（#28 缺口一的決定）。卡種對應頁
  不呈現金額，所以不放。

### 行情新鮮度警示（`_market_freshness.html`，收藏總覽與持有品）

**只在出狀況時出現**：從未成功、超過 24 小時沒成功、這一輪進行中、失敗、匯率沒抓到、
個別卡種抓失敗。健康時整塊不渲染——「有東西跳出來」本身就代表出事了。過期時附
`立即更新行情` 按鈕。卡種對應頁不顯示（#28 缺口二）。

### `/` 收藏總覽（由上而下）

1. **行情警示**（只在出狀況時）
2. **Hero**（`_portfolio_hero.html`）— 資產走勢與持有摘要合成一整片
   - 桌機約 7:3：左邊走勢圖，右邊持有摘要；手機上摘要排在走勢圖**之前**
   - 摘要只講**持有中**：總市值（全頁最大的數字）、未實現損益、報酬率、成本、
     張數與卡種數；有沒市值的張數時明講「還有 N 張沒有市值」。已實現損益不在這裡
   - 走勢圖：單條總市值面積線、中性色（ADR-0025）；區間鈕 `7D / 1M / 3M / YTD / ALL`，
     跨度不足一年時沒有 `YTD`，沒有 `1D`
3. **卡圖牆**（`_portfolio_wall.html`）— 一格一個卡種，文字分頁「持有中／已售出」
   - 卡圖比例 `63 / 88`（實體卡尺寸）、`object-fit: contain`、不裁切
   - 桌機 `repeat(auto-fill, minmax(11rem, 1fr))`（約六欄），手機固定兩欄
   - 格子上只有：卡名、系列與編號、張數、報酬率（算不出就是 `—`）
   - 已售出的卡圖維持全彩
4. **卡片明細抽屜** — 點一格開 `<dialog>`，牆面不重排
   - 桌機從右側滑出約 460px；手機全螢幕
   - 持有中：合計現值／總成本／未實現損益／報酬率 → 單張市值（並列樣本筆數與
     期間，或已過期天數）→ 動能（**打開時才取**）→ 流動性（兩個半邊並列）→ 逐筆
   - 已售出：講收藏史不講市場——總成本／總售出／已實現損益，逐筆「購入 → 售出」
   - **唯讀**：抽屜裡沒有增刪改，只有「查看持有品明細 →」

### `/holdings` 持有品

- 頂端是即時搜尋（打字就篩卡名、系列代碼、卡號，純前端）與 `新增卡種`
- **以卡種分組**：每組一個表頭（卡圖、持有中／已售出張數、持有成本、市值／張附樣本、
  未實現損益），底下一張表列出**每一筆**實體持有品，持有中與已售出並排
- 每一筆有自己的損益；`售出` 從該列啟動；低頻動作（刪除、改回持有中）收在 `⋯` 次選單
- 不重複首頁的儀表板數字
- 表格包在 `.tblwrap` 裡，允許表格自己橫捲（頁面本身不捲）

### `/queue` 卡種對應

- 輕量摘要：只有「待處理」在有工作時被強調
- **一次只處理一個**：左邊我的卡種，右邊 SNKRDUNK 候選卡圖。選候選與確認對應是
  兩個步驟；`跳過` 不改任何資料；`不納入行情` 收在 `⋯` 次選單，確認對話框說清楚效果
- 「沒有找到候選」（中性）與「無法取得候選」（錯誤，可重試）長得不一樣
- 確認後自動換下一張，成功回饋用 toast，不跳對話框
- 沒有待處理時給一句話，不畫空表格
- 下方是歷史：兩個分頁＋即時篩選，以「我的卡種 ↔ SNKRDUNK 卡」呈現，預設畫面
  不出現技術 ID

## 3. 樣式架構：共用 design foundation，頁面版面分離（ADR-0023）

```
static/design.css      ← 全站共用：色票 token、字體、間距、圓角、按鈕、輸入、分頁、
   │                      狀態、頁首、表格、對話框／抽屜基礎、⋯ 次選單、toast、
   │                      Hero 數字、tile、候選卡、空狀態一句話
   ├─ portfolio.css    ← 只放首頁：Hero 版面、走勢圖、卡圖牆、明細抽屜內容
   ├─ holdings.css     ← 只放持有品：搜尋列、卡種分組
   └─ queue.css        ← 只放卡種對應：焦點工作區、候選清單、歷史
```

每一頁先載 `design.css`，再載自己那支。規矩：

- **頁面 CSS 一律引用 token，不寫死顏色**。同一個語意只有一個寫法，不會在三頁漂移
  成三種顏色。
- **需要新的共用元件時改 `design.css`，並想清楚會影響三頁**。只有一頁用到的就留在
  那一頁的檔案裡。

重做前的「三頁樣式各寫一份、只共用 markup 不共用樣式」已經被 ADR-0023 推翻。

### 共用的樣板片段

`templates/` 底下 `_` 開頭的是被 `{% include %}` 進去的片段：

| 片段 | 內容 | 被誰用 |
|---|---|---|
| `_app_shell.html` | 全站頁首、toast 容器與 `showToast()` | 三頁 |
| `_market_freshness.html` | 行情警示 | `/`、`/holdings` |
| `_market_script.html` | 更新行情的行為（`crawlMarket()`） | `/`、`/holdings` |
| `_holding_editor.html` | 持有品增刪改的對話框與行為 | `/`、`/holdings` |
| `_portfolio_hero.html` | Hero（走勢＋摘要）與走勢圖腳本 | `/` |
| `_portfolio_wall.html` | 卡圖牆、明細抽屜與其腳本 | `/` |

Hero 與卡圖牆拆成兩個片段（#29），所以兩者可以分開修改，不會互相衝突。

## 4. 視覺語彙

色值以 `design.css` 的 `:root` 為準，下表只列語意。

| 用途 | token | 值 |
|---|---|---|
| 頁面底／區塊／浮起層 | `--bg-app` / `--bg-surface` / `--bg-elevated` | `#0B0F14` / `#111821` / `#18212B` |
| 框線 | `--border-default` / `--border-strong` | `#26313D` / `#364453` |
| 主要／次要／微中繼文字 | `--text-primary` / `--text-secondary` / `--text-muted` | `#E6EDF3` / `#A0AEC0` / `#8494A8` |
| 連結、焦點、主要按鈕、作用中分頁 | `--accent` | `#6EA8FE` |
| 上漲／獲利 | `--positive` | `#59C98C` |
| 下跌／虧損 | `--negative` | `#F07178` |
| 警示（過期、匯率抓不到） | `--warning` | `#D9A441` |
| 危險動作（刪除） | `--danger` | `#F07178` |

`--text-muted` 是使用者拍板從 `#718096` 上調的，讓 12–13px 的小字在兩種底色上都
過 WCAG AA 4.5。框線刻意不做 3:1 強對比（spec §4.7），結構主要靠表面色調區分。

其他慣例：

- **數字一律 `tabular-nums`**（等寬數字，`.tnum`），縱向對得齊
- **顏色只用在有方向的數字上**（報酬率、損益，`.dir-up` / `.dir-down`）。市值、成本、
  張數、成交筆數這些中性數字不著色。走勢線是中性色——它講的是「總市值多少」，
  不是「賺賠」
- **陰影只給真正浮起的層**（抽屜、對話框、tile hover），Hero 與一般區塊不加
- **不足與空狀態各有各的樣子**，不能合併成同一種灰字：
  - 這個卡種近期沒成交 → 琥珀色「已過期 N 天」
  - 整個系統沒更新成功 → 行情警示橫幅
  - 指標還沒到位 → `.status-pending`（「資料累積中」「敬請期待」）＋一句為什麼
  - 候選來源失敗 → 錯誤狀態容器＋重試，與「沒有找到候選」的中性狀態不同

## 5. 不可協商的約束

以下每一條都來自 `CONTEXT.md` 或 ADR，**改介面時不能違反**。它們看起來像細節，
但每一條都是為了不讓畫面說謊。每一條後面附上現在的介面怎麼守住它。

1. **缺數字就讓它不存在，不顯示 0，也不顯示 `—` 以外的假值。**
   0 會被讀成「不賺不賠」「不漲不跌」，那是把缺資料講成一個結論。
   → 卡圖牆算不出報酬率給 `—`；持有品頁沒有市值時損益欄給 `—`。
2. **未實現損益與已實現損益永不混入同一個數字。** 兩者必須分開呈現。
   → Hero 只講持有中；已實現只出現在已售出分頁與持有品頁的已售出列。
3. **報酬率一律 `(結果 − 成本) ÷ 成本`，不使用倍數。** 全站唯一定義。
4. **市值旁必須並列樣本形狀**（幾筆成交／涵蓋哪段期間）。ADR-0015。
   一個由兩筆成交撐起來的價，與由二十筆撐起來的價，不該長得一模一樣。
   → 明細抽屜與持有品頁的「市值／張」都並列「N 筆 · 起～迄」或「已過期 N 天」。
5. **走勢圖的資料逐日帶涵蓋率。** ADR-0021 定義、ADR-0025 把它從畫面上拿掉：
   `/api/portfolio` 的 trend 仍回傳每天的 `valued_kind_count`／`held_kind_count`，
   圖上不顯示。曲線前段的爬升有一部分是涵蓋率補齊，不是行情——這是使用者接受的取捨。
   → Hero 摘要明講「還有 N 張沒有市值」。
6. **行情過期時必須在有市值的畫面上出聲。** 停擺的爬取若不出聲，三週前的數字
   看起來與今天的一模一樣。
   → 收藏總覽與持有品頁共用同一個警示片段，過期時整塊琥珀＋立即更新。
   （重做前這條寫成「新鮮度必須與市值同畫面」。uiux-spec §7.2 改為健康時不顯示，
   使用者裁決照 spec：這條防的是「過期時被誤導」，那個意圖保住了；少掉的只是健康時
   看得到「幾小時前」，那不是誠實性問題。）
7. **空狀態不是暫時的鷹架。** 新買進的卡種永遠會經歷「還沒有動能」的階段，資料補齊
   之後這個狀態依然存在。它要長得像刻意的設計，不是壞掉的畫面。
   → `.status-pending` 標籤＋一句說明；卡種對應沒有待處理時給一句話而不是空表格。
8. **流動性的兩個半邊必須並列**，不可以只先開熱門度那一半。存世多但成交少，與存世
   多且成交多，是完全不同的兩張卡。
   → 抽屜裡「PSA 10 張數」與「近 3 月成交」並列，目前兩邊都是「敬請期待」。
   熱門度另有一個已知的低估問題，見 #17。
9. **沒有市值的卡種仍然要留在牆上。** 消失會被讀成「我少了一張卡」，那比一格沒有
   數字嚴重得多。
10. **手機是主要的唯讀場景，首頁永不橫向捲動。** 卡圖牆用 `auto-fill` 自己換行、
    手機固定兩欄，刻意不用表格。（`/holdings` 的表格可以在 `.tblwrap` 裡自己橫捲，
    頁面本身不捲。）
11. **刪除持有品前必須明確確認，且說得出是具體哪一筆**（卡種、購入日、成本），
    已售出的還要說出會讓已實現損益少多少。不是一句抽象的「確定嗎」。
    → 刪除收在 `⋯` 次選單，確認對話框帶這幾個數字。

## 6. 改介面時，測試會擋你哪裡

所有頁面測試都走同一個接縫（seam，測試接觸系統的那個面）：

```
TestClient → GET / | /holdings | /queue | /static/*.css → 對回傳的 HTML／CSS 字串斷言
```

沒有瀏覽器測試。**響應式與視覺（不橫捲、六欄／兩欄、抽屜寬度）沒有任何測試保護**，
只能用眼睛驗（見 §7.3 的寬度清單）。這是 #28 明知的取捨，不是疏漏。

判準是專案自己的規範：**重寫實作但行為不變時，測試不該紅。** 斷言分三層，紅了先
分清楚屬於哪一層。

### 第一層：紅線，不能違反

守的是 §5 的約束。紅了代表畫面開始說謊，**要改的是設計不是測試**。

```python
assert "倍" not in html                               # 報酬率不用倍數
assert f"{value['sample_count']} 筆" in html          # 市值必並列樣本（ADR-0015）
assert "已過期 41 天" in html                          # 近 30 天無成交要說出過期天數
assert 'class="status-pending">資料累積中' in page     # 動能的空狀態有明確文字
assert 'class="status-pending">敬請期待' in page       # 流動性的空狀態有明確文字
assert "PSA 10 張數" in page                           # 流動性要說出兩個半邊
assert "Mew" in html                                   # 沒有市值的卡種仍在牆上
assert 'name="viewport"' in page                       # 手機讀得到
```

金額與百分比的格式斷言（`{:,}`、`{:+.1%}`）也屬於這一層：數字要顯示，而且全站
同一種寫法。

### 第二層：意圖對，寫法綁住實作

集中在 `test_card_wall.py`，重做時已改寫成對 CSS 檔斷言，並把意圖寫進註解：

```python
assert "repeat(auto-fill" in css.text          # 意圖：格子自動換行、桌機欄數隨寬度長
assert "overflow-x" not in css.text            # 意圖：首頁本身永不橫向捲動
assert "<table" not in html                    # 意圖：卡圖牆不用表格排版
assert 'id="wall-tab-held" checked' in html    # 意圖：持有中是預設分頁、不靠 JS
assert 'class="tblwrap"' in page               # 意圖：持有品頁的表格可自己橫捲
assert f"{momentum['return_rate']:+.1%}" not in page   # 意圖：動能不隨頁面一起算
```

改成 container query、改 JS 分頁、重新命名 class 時，這些會「誤紅」。遇到時**改寫
斷言對應新實作，保留意圖註解**，不要刪掉。

### 第三層：綁住 JS 函式名與 data 屬性

約四十條，集中在 `test_portfolio_actions.py`、`test_holdings_crud.py`、
`test_mapping_*.py`：

```python
assert 'onclick="openSale(this)"' in page    # 還有 openCreate / openEdit / openUnsell / openDelete
assert 'onclick="confirmSelected(this)"' in html   # 還有 openExclude / openUndo / retryCandidates
assert 'data-purchase="2026-03-15"' in page  # 還有 data-cost / data-kind / data-realized / data-sold
assert 'data-search="mega lucario m2a 228"' in page
assert "location.reload()" in page
```

意圖是「操作入口就在那一筆旁邊」「確認訊息說得出是具體哪一筆」「操作完成畫面自動
反映」——後兩件事是 §5 第 11 條的紅線，**但用什麼函式名、什麼屬性名完全不是**。
前端重寫時這一層會整批紅，這是預期中的；圍繞新的行為契約重寫它們。

### 實務建議

1. 動工前先跑 `uv run python -m pytest -q`，記下基準線（2026-11-13：**367 passed**）
2. 每改一塊就跑一次，只看**新增**的紅燈
3. 新增的紅燈先問「屬於哪一層」，再決定改設計還是改測試
4. 第一層紅了就停下來——那代表畫面正在說謊，不是版面問題

### 7.4 卡牌立體特效（傾斜＋反光）— 已實作（選 A，手寫），見 ADR-0024

起點是這個 repo：<https://github.com/simeydotme/pokemon-cards-css>（GPL-3.0，8.2k star，
CSS-Tricks 上那篇 holographic trading card effect 的出處）。作者在 README 置頂自薦了一個
輕量版：<https://github.com/simeydotme/hover-tilt>（MIT）。

以下是 2026-09-13 讀過兩邊原始碼之後的盤點（歷史紀錄）。**後來實作時改為手寫，見 ADR-0024。**

#### 能用的是「傾斜＋反光」，不是「彩虹 holo」

那個特效是分層疊出來的，而**兩層的可用性天差地遠**：

```
.card                     ← 3D 透視容器（perspective: 600px）
 └ .card__translater      ← 位移＋縮放
    └ .card__rotator      ← rotateX / rotateY ── 滑鼠帶動的傾斜
       ├ img              ← 卡面圖
       ├ .card__shine     ← 彩虹 holo 層 ✗ 本專案用不了
       └ .card__glare     ← 反光層       ✓ 可以用
                             ↑ 兩層都靠 CSS 變數驅動：
                               --pointer-x/y、--pointer-from-center、
                               --rotate-x/y、--background-x/y、
                               --card-scale、--card-opacity
```

`glare`（反光）是一個跟著游標跑的放射狀白光 ＋ `mix-blend-mode: overlay`，**不挑卡**。
`shine`（彩虹 holo）是重複線性漸層 × 材質圖 × blend-mode × `clip-path`，**很挑卡**。

**四個理由讓 `shine` 在本專案用不了：**

1. **沒有稀有度資料，而且是刻意沒有。** 那 20 幾支 rarity CSS 是靠 `data-rarity="rare holo"`、
   `data-subtypes` 這些屬性派送的。但 `CONTEXT.md` 明文「不區分鑑定公司、不區分分數」，
   **稀有度還列在 `_Avoid_` 清單**（rarity 在寶可夢卡指卡面印刷的稀有度符號，與本系統的
   流動性概念無關）。`card` 表只有 `series_raw` / `number_raw` / `card_code` / `name_en` /
   `name_ja`，沒有 rarity 欄位。派不出去。
2. **`clip-path` 寫死官方卡框幾何。** `--clip: inset(9.85% 8% 52.85% 8%)` 指的是「標準卡框的
   圖框視窗」。我們的圖是 SNKRDUNK 商品照裁切過的，裁切幅度不一致（§7.2 的
   `744296.webp` 比例 1.095 就是異常值）。對不準就是一塊歪掉的色帶。
3. **卡圖是實拍，holo 已經烙在照片裡。** `91147.webp`（リザードン V SR）照片上的彩虹紋路
   是拍出來的。再疊一層合成彩虹＝雙重 holo。
4. **效能。** 62 格 × 5 層，每層帶
   `will-change: transform, opacity, background-image, background-size, background-position,
   background-blend-mode, filter`。§5 第 10 條說手機是主要的唯讀場景。

**一個值得記下的巧合**：那份 CSS 的 `--card-aspect: 0.718`，與 §7.1 實測 69 張卡圖的中位比例
`0.718`、以及最後採用的 `63/88`（0.716）幾乎完全一致。它本來就是照實體卡比例寫的。

> 實作時的補充（ADR-0024）：使用者看過樣品後選了「整卡彩虹光帶，但淡一點」。它與 shine 不同，
> 所有卡套同一種光帶，不需要稀有度資料；理由 3 的雙重 holo 疑慮使用者看過後接受，透明度降到 .3 減輕之。

#### 兩個候選做法

| | **A. 只用在卡片明細抽屜** | **B. 卡圖牆 62 格也上** |
|---|---|---|
| 範圍 | 一次一張大卡（`_portfolio_wall.html` 的 `.drawer__art`） | 每一格 `.wall .art` |
| 效能風險 | 無。同時只有一張在動 | 高。要節流（只對 hover 中那格啟用）、要實測手機 |
| 動機是否對得上 | 對。抽屜本來就是「仔細看這張卡」的場景 | 牆的任務是「用認圖的方式找卡」，特效反而干擾掃視 |
| 工作量 | 小 | 中，且有效能風險要先實測 |
| 對 §5 約束的影響 | 無 | 無（特效不改任何數字），但捲動流暢度是體感風險 |

還有第三條路留著：**不引入任何檔案，自己移植 `base.css` 的 glare 那段 ＋ 約 40 行 vanilla JS。**
好處是零依賴、沒有授權問題；代價是彈簧物理（spring）的手感要自己調，不會像原版那麼順。

#### 決定：暫定 A

理由是**先用最小的代價看到效果**。A 做完之後如果覺得值得，再決定要不要往牆上推；
**B 不該在沒看過 A 的實際效果之前就做**——它的成本幾乎全在效能調校上，而那筆成本只有在
「已經確定這個特效值得」之後才划算。

什麼情況下才該重新考慮 B：A 上線後實際用了一陣子，**而且**在手機上實測 62 格同時掛載
特效的捲動幀數可以接受。

#### 用 hover-tilt 而不是 pokemon-cards-css

> 已改為手寫，見 ADR-0024（動工前發現 npm 標 MPL-2.0、GitHub 標 MIT，授權不一致，且 bundle 內含 Svelte runtime）。

| | pokemon-cards-css | **hover-tilt** |
|---|---|---|
| 授權 | GPL-3.0（傳染性 copyleft） | **MIT** |
| 形式 | Svelte 專案 ＋ 27 張材質圖 ≈ 4.4 MB | **Web Component**，`dist/hover-tilt.js` 單檔 180,717 bytes |
| 建置步驟 | 要 Vite | **不用**，`<script type="module">` 就跑 |
| 前端框架 | Svelte | **原始碼裡沒有**（Svelte runtime 已編進那支檔案） |
| 稀有度資料 | 必要 | 不需要 |

介面（v1.0.0）：`<hover-tilt tilt-factor="1.5" scale-factor="1.05" glare-intensity="0.8">`，
屬性用 kebab-case，對外露出 `--hover-tilt-opacity` / `--hover-tilt-rotation-x/y` 等 CSS 變數，
內部可用 `::part(container)` / `::part(tilt)` 調整。

#### 實作前必須先處理的四件事

1. **這會動到 §1 的兩條明文性質**，所以**要補一張 ADR**，不要順手做掉：
   - 「零外部資源」——把 `hover-tilt.js` 抓下來放進 `src/card_collection/static/` 就守得住
     （跟 `design.css` 一樣是本機檔案，npm 或任何 CDN 掛掉都不影響）。要在 ADR 裡明講
     這條規矩的意思是「**執行期不依賴外部網站**」而不是「不准用別人的程式碼」。
   - 「沒有前端框架」——那支檔案裡面**包著一份 Svelte runtime**。原始碼裡看不到框架，
     但它確實在 bundle 裡。這是取捨，要寫明白，不要假裝沒這回事。
2. **`prefers-reduced-motion`** 要處理。
3. **`.art` 目前是 `object-fit: contain` ＋ 深色底**（§7.1 的決定）。卡圖四周有留白時，
   傾斜與反光會作用在「圖片元素」而不是「卡的形狀」上，看起來會怪。要先確認反光層是
   貼著卡面還是貼著容器。
4. **測試**：這個改動不碰任何數字，§6 第一層的紅線一條都不會動到。頂多動到第二層
   （CSS 類別名）。

#### 不要走的路

- 不要為了讓 `shine` 能用而去補一個 rarity 欄位。那會把 `CONTEXT.md` 明文排除的概念
  請回系統裡，代價遠大於視覺收穫。
- 不要用 CDN 載 `hover-tilt`。§1 那條規矩的存在理由就是這個。

### 7.5 頁面背景圖（個人檔案，不進 git）

三頁共用一張半透明背景圖，疊在 `body` 的深色底之上、內容之下（`design.css` 的
`body::before`）。

- 圖檔放在 `src/card_collection/static/local/background.webp`，該目錄已列入
  `.gitignore`：這是有版權的美術圖，本 repo 是公開的，**不要 commit**。
- 透明度是 `design.css` 的 `--bg-image-opacity`（目前 `.4`），要調淡調濃改這一個值。
- 圖檔不存在時（例如別人 clone 這個 repo）`url()` 載入失敗、什麼都不畫，頁面照常是深色底。
- ADR-0022 的深色主題前提沒變，只是多疊了一層圖。
- 圖寬撐滿頁寬、高度照原比例，從頁面頂端開始隨內容捲動，往下以 `repeat-y` 重複接續。
- **換圖要跑前處理腳本**，不要直接覆蓋檔案：

  ```
  uv run python scripts/prepare_background.py C:\path\to\image.png
  ```

  它會裁掉四周黑邊（放大後兩張接起來會變一條粗黑線）、把上下邊緣各 8% 淡成頁面底色
  （交界才不會硬切），再存成 webp。腳本裡的底色必須與 `--bg-app` 一致，有測試守著。

## 8. 資料從哪裡來

畫面上的每個數字都是伺服器算好的，前端**不重算任何金額**。

| 端點 | 餵給誰 |
|---|---|
| `GET /api/portfolio`（`/` 也直接用同一份資料渲染） | Hero 摘要、走勢圖、行情新鮮度、卡圖牆與抽屜內容 |
| `GET /api/cards/{apparel_id}/holdings` | 明細抽屜**打開時**才取：動能 |
| `GET /api/cards/{apparel_id}/image` | 卡圖 |
| `POST /api/market/crawl` | 「更新行情」 |
| `POST/PATCH/DELETE /api/holdings...`、`POST /api/card-kinds` | 持有品增刪改、新增卡種 |
| `/api/mapping/...` | 卡種對應的候選、確認、不納入行情、推翻 |

兩個值得知道的設計：

- **走勢圖的資料一次全給**。`ALL` 是其他四個區間的超集合，切區間是在瀏覽器裡切片，
  零延遲、不打 API。
- **動能是打開抽屜那一刻才取的**，卡圖牆的列表回應不背負它。牆上有六十幾格，為了
  使用者實際會打開的那一兩格，把其餘全部都算一次並不划算。市值、成本、損益本來就在
  頁面資料裡，抽屜直接複製該格的 `<template>`，不重取。
